How Open Draft was built

Version 0.2.0
Released October 17, 2026
Status: working prototype; independent of Wikimedia.

Design and development

The project owner defined the purpose, wiki-first priorities, accessibility requirements, and open-education guidance. OpenAI Codex assisted with the design, programming, documentation, and automated testing. This is AI-assisted development; it has not received an independent human accessibility audit.

Two design reviews preceded implementation: one examined contributor workflows and wiki destinations; the other examined accessibility, local storage, privacy, and failure handling. The implementation was then tested and revised. The source package includes DESIGN-REVIEW.md and QA.md so maintainers can inspect those decisions and their limits.

New in version 0.2.0

The wiki translator adds a visual rich-text editor beside live wiki code, optional paired colors with contrast warnings, and UDL suggestions with explanations and starters. Translator drafts are saved with the project. The editor uses native browser editing commands; cross-browser and screen-reader evaluation is still needed.

The technology

  • Interface: HTML5, CSS, and plain JavaScript. Native controls, explicit labels, keyboard move controls, responsive layouts, and print styles support access and maintenance.
  • Content model: versioned JSON holds pages, structured blocks, citations, media, rights records, and review acknowledgments.
  • Local file handling: browser FileReader, Blob, and download APIs read selected files and produce local downloads. Images are embedded in the editable project file.
  • Temporary work: sessionStorage retains a tab’s working copy when available. Users can clear it or choose memory-only operation. Downloaded project files are the portable backup.
  • Wiki exports: custom serializers create Wikibooks page source and Commons image-description drafts. JSZip 3.10.1 assembles the contribution ZIP in the browser.
  • Hosting: static files suitable for GitHub Pages. No compilation, package installation, server application, account, or API key is needed to run the deployed app.

The running app does not use an AI model, analytics, remote fonts, or a file-processing service. AI assistance was used during development, not to process visitors’ content. Hosting requests still reach the hosting provider, and external links visit their respective websites.

How it was checked

The initial prototype passed 21 model/export tests and scripted browser workflows using Node.js, Playwright, and Microsoft Edge. axe-core 4.10.3 reported no violations in the tested screens and reading export; some native-control contrast checks remained incomplete. Desktop/mobile screenshots and a sample print proof were also inspected.

Version 0.2.0 passed all 28 model/export tests and the extended browser workflow, including translator formatting, color thresholds, starter undo/redo, and saved-project recovery.

These checks are evidence of testing, not a certification. Full screen-reader, keyboard-task, cross-browser, and actual wiki-sandbox evaluation remain necessary. IMSCC, EPUB, and verified accessible PDF conversion are future work.
